# 교내 분실물 관리 서비스 — Use Case Description

## 공통 표기

| 표기 | 의미 |
|---|---|
| `[논의]` | 고객 또는 운영 주체와 결정이 필요한 사항. 확정된 동작으로 해석하지 않는다. |
| 성공 | 유스케이스의 사용자 목표가 충족된 상태. |
| 실패·취소 | 사용자 목표를 완료하지 못했거나 사용자가 중단한 상태. 개인정보·실제 데이터는 저장하지 않는다. |

## UC_01 — 분실물 조회 및 문의 안내

| 항목 | 내용 |
|---|---|
| ID / 이름 | UC_01 / 분실물 조회 및 문의 안내 |
| 상태 / 우선순위 | 확정 / 높음 |
| 주 액터 | 분실 학생 |
| 사용자와 목표 | 분실 학생이 잃어버린 물품의 보관 여부와 위치를 조회하고, 필요하면 담당 부서의 문의 방법을 확인하여 행정실의 불필요한 방문 없이 다음 행동을 결정한다. |
| 관련 고객 요구·정책 ID | NEEDS_1, NEEDS_4, NEEDS_6 / FR_01, FR_04, NFR_01, NFR_03, NFR_04 / Pol_01, Pol_03, Pol_06, Pol_07 |
| 사전조건 | 조회에 사용할 가상 분실물 데이터가 시스템에 등록되어 있다. 공개 가능한 정보 항목은 운영 정책에 따라 설정되어 있다. |
| 시작 사건 | 분실 학생이 분실물 조회를 시작한다. |
| 기본 흐름 | 1. 분실 학생이 물품을 찾기 위한 조회 조건을 입력한다.<br>2. 시스템은 조건에 맞는 공개 가능한 분실물 정보를 조회한다.<br>3. 시스템은 보관 여부와 보관 위치를 표시한다.<br>4. 분실 학생은 조회 결과를 확인한다.<br>5. 분실 학생이 문의가 필요하면 문의 안내를 요청한다.<br>6. 시스템은 담당 부서와 정해진 문의 방법을 표시한다.<br>7. 분실 학생은 조회 또는 문의 안내 결과를 바탕으로 다음 행동을 결정한다. |
| 대안·예외 흐름 | A1. **분기 지점:** 2단계 → **조건:** 조회 조건에 맞는 공개 가능 물품이 없음 → **대응:** 시스템은 일치하는 물품이 없음을 안내한다. [논의] 재조회 방법 또는 담당 부서 문의 안내를 함께 표시할지 결정 필요 → **복귀/종료:** 사용자는 조건을 바꿔 1단계로 복귀하거나 유스케이스를 종료한다.<br><br>A2. **분기 지점:** 3단계 → **조건:** 물품이 `인도 완료` 상태임 → **대응:** 시스템은 인도 완료 상태임을 보관 중인 물품과 구분해 표시한다. [논의] 인도 완료 물품의 보관 위치를 표시할지 결정 필요 → **복귀/종료:** 4단계로 복귀한다.<br><br>A3. **분기 지점:** 5단계 → **조건:** 사용자가 문의 안내를 요청하지 않음 → **대응:** 시스템은 추가 문의 안내를 표시하지 않는다 → **복귀/종료:** 7단계로 진행한다.<br><br>A4. **분기 지점:** 6단계 → **조건:** 담당 부서 또는 문의 방법이 설정되지 않음 → **대응:** 시스템은 문의 안내를 제공할 수 없음을 기록·안내한다. [논의] 사용자에게 표시할 대체 안내 및 운영 담당자 통보 방식 결정 필요 → **복귀/종료:** 유스케이스를 종료한다. |
| 사후조건 — 성공 | 조회 결과가 제공되며, 필요 시 담당 부서와 문의 방법이 제공된다. 개인 휴대전화 번호와 실제 개인정보는 표시·저장되지 않는다. |
| 사후조건 — 실패·취소 | 조회 조건이 맞지 않거나 사용자가 중단하면 물품 정보는 변경되지 않는다. 실패 원인·접속 이력의 저장 여부는 미확정이며, 저장 시에도 실제 개인정보를 포함하지 않는다. |
| 미확정 사항·고객 질문 | Q1. 조회 조건은 무엇인가(물품 분류, 습득 장소, 습득 일자, 키워드 등)?<br>Q2. 보관 여부·위치 외에 공개할 항목은 무엇이며, 정보보호 담당자가 최종 승인하는가?<br>Q3. 문의 안내는 조회 결과 안에서만 제공하는가, 별도 화면에서도 제공하는가?<br>Q4. 담당 부서명, 문의 방법, 운영 시간 중 어떤 항목을 제공하는가?<br>Q5. 조회 결과가 없을 때 재조회·문의 안내를 어떻게 제공할 것인가? |
| 추가 검증 기준 | 대표 사용자 10명 이상 중 90% 이상이 도움 없이 3분 이내에 보관 여부·위치·문의 방법을 확인해야 한다. 조회 요청의 95%는 3초 이내에 결과를 반환해야 한다. 측정 환경과 동시 사용자 수는 미확정이다. |

## UC_02 — 습득물 등록

| 항목 | 내용 |
|---|---|
| ID / 이름 | UC_02 / 습득물 등록 |
| 상태 / 우선순위 | 확정 / 높음 |
| 주 액터 | 습득 학생, 행정 담당자 |
| 사용자와 목표 | 습득 학생은 주운 물품을 앱에서 바로 등록하여 분실자가 물품 정보를 확인할 수 있게 한다. 행정 담당자는 분실물 센터의 습득 물품을 등록하여 센터 보관 물품을 관리한다. |
| 관련 고객 요구·정책 ID | NEEDS_2, NEEDS_7 / FR_02, NFR_02, NFR_03 / Pol_01, Pol_07 |
| 사전조건 | 등록 주체가 물품 정보 입력을 시작할 수 있다. 시스템은 가상 데이터만 사용한다. [논의] 사용자 식별·권한 확인 방식은 학교 인증 연동 범위 밖이며 별도 결정이 필요하다. |
| 시작 사건 | 습득 학생 또는 행정 담당자가 습득물 등록을 시작한다. |
| 기본 흐름 | 1. 등록 주체가 습득물 등록을 선택한다.<br>2. 시스템은 등록 항목을 표시한다.<br>3. 등록 주체가 습득 물품 정보를 입력한다.<br>4. 등록 주체가 등록을 요청한다.<br>5. 시스템은 입력값을 확인하고 물품 정보를 등록한다.<br>6. 시스템은 등록 결과를 등록 주체에게 안내한다. |
| 대안·예외 흐름 | A1. **분기 지점:** 3~4단계 → **조건:** 필수 항목이 누락되었거나 형식이 맞지 않음 → **대응:** 시스템은 보완이 필요한 항목을 표시하고 등록을 완료하지 않는다. [논의] 역할별 필수 항목과 입력 형식 결정 필요 → **복귀/종료:** 3단계로 복귀한다.<br><br>A2. **분기 지점:** 4단계 → **조건:** 사용자가 등록을 취소함 → **대응:** 시스템은 등록 요청을 처리하지 않는다. [논의] 임시 저장 제공 여부와 보존 기간 결정 필요 → **복귀/종료:** 유스케이스를 종료한다.<br><br>A3. **분기 지점:** 5단계 → **조건:** 습득 학생이 등록한 물품을 즉시 공개할 수 없음 → **대응:** 시스템은 등록은 보존하되 공개 상태를 결정한다. [논의] 행정 담당자의 인수·검토·승인 절차 및 분실 학생에게 보이는 상태 결정 필요 → **복귀/종료:** 6단계로 진행하거나 승인 대기 상태로 종료한다.<br><br>A4. **분기 지점:** 5단계 → **조건:** 등록 처리 중 시스템 오류 발생 → **대응:** 시스템은 등록 성공 여부를 명확히 안내한다. [논의] 재시도, 중복 등록 방지 및 오류 기록 방식 결정 필요 → **복귀/종료:** 성공하지 않은 경우 3단계로 복귀하거나 종료한다. |
| 사후조건 — 성공 | 등록된 습득물 정보가 보존된다. 공개·조회 가능 시점과 초기 보관 상태는 운영 절차에 따라 결정된다. 실제 개인정보와 개인 휴대전화 번호는 저장·표시하지 않는다. |
| 사후조건 — 실패·취소 | 등록이 완료되지 않으면 확정 물품 정보는 생성·변경되지 않는다. 임시 입력값의 보존 여부는 미확정이다. |
| 미확정 사항·고객 질문 | Q1. 습득 학생과 행정 담당자의 필수 입력 항목은 같은가? 다르면 역할별 항목은 무엇인가?<br>Q2. 습득 학생이 등록한 물품은 즉시 조회 가능한가, 행정 담당자의 인수·검토·승인 후에만 가능한가?<br>Q3. 행정 담당자는 습득 학생의 등록 내용을 수정·반려할 수 있는가? 그 사유와 이력도 관리해야 하는가?<br>Q4. 등록 취소 시 임시 저장을 제공하는가? 제공한다면 보존 기간은 얼마인가?<br>Q5. 동일 물품의 중복 등록을 어떻게 처리하는가? |
| 추가 검증 기준 | 필수 항목 확정 후, 물품 실물 확인 시간을 제외한 등록 과제의 90% 이상이 3분 이내에 완료되어야 한다. 습득 학생과 행정 담당자별 기준선 및 최종 목표는 미확정이다. |

## UC_03 — 분실물 보관·인도 상태 관리

| 항목 | 내용 |
|---|---|
| ID / 이름 | UC_03 / 분실물 보관·인도 상태 관리 |
| 상태 / 우선순위 | 확정 / 높음 |
| 주 액터 | 행정 담당자 |
| 사용자와 목표 | 행정 담당자가 관리 대상 물품의 상태를 `보관 중` 또는 `인도 완료`로 기록·구분하여, 실제로 인도된 물품과 보관 중인 물품을 혼동하지 않고 반복 문의를 줄인다. |
| 관련 고객 요구·정책 ID | NEEDS_3 / FR_03, NFR_03 / Pol_01, Pol_07 |
| 사전조건 | 관리할 물품 정보가 등록되어 있다. 행정 담당자가 상태 관리 권한을 가진다. [논의] 권한 확인 방식과 상태 변경 가능 대상은 미확정이다. |
| 시작 사건 | 행정 담당자가 등록된 물품의 보관·인도 상태를 확인하거나 변경할 필요가 생긴다. |
| 기본 흐름 | 1. 행정 담당자가 관리할 물품을 선택한다.<br>2. 시스템은 현재 보관·인도 상태를 표시한다.<br>3. 행정 담당자가 상태를 `보관 중` 또는 `인도 완료`로 선택한다.<br>4. 행정 담당자가 변경을 요청한다.<br>5. 시스템은 상태를 기록하고 변경 결과를 표시한다.<br>6. 이후 조회 시 시스템은 변경된 상태를 보관 중인 물품과 구분하여 표시한다. |
| 대안·예외 흐름 | A1. **분기 지점:** 1단계 → **조건:** 대상 물품을 찾을 수 없음 → **대응:** 시스템은 대상 물품이 없음을 안내한다. [논의] 물품 검색·선택 기준 결정 필요 → **복귀/종료:** 1단계로 복귀하거나 종료한다.<br><br>A2. **분기 지점:** 3~4단계 → **조건:** 상태 변경 권한이 없거나 변경 조건을 충족하지 않음 → **대응:** 시스템은 상태를 변경하지 않고 사유를 안내한다. [논의] 권한 주체와 변경 조건 결정 필요 → **복귀/종료:** 유스케이스를 종료한다.<br><br>A3. **분기 지점:** 5단계 → **조건:** 잘못된 상태 변경이 확인됨 → **대응:** 시스템은 정정 절차에 따라 상태를 바로잡는다. [논의] 정정 권한, 승인 절차 및 변경 이력 보존 여부 결정 필요 → **복귀/종료:** 정정이 완료되면 6단계로 진행하고, 불가하면 종료한다.<br><br>A4. **분기 지점:** 5단계 → **조건:** 상태 저장 중 오류 발생 → **대응:** 시스템은 저장 성공 여부를 안내하고, 성공하지 않은 경우 기존 상태를 유지한다. [논의] 재시도·오류 기록 방식 결정 필요 → **복귀/종료:** 3단계로 복귀하거나 종료한다. |
| 사후조건 — 성공 | 대상 물품의 상태가 `보관 중` 또는 `인도 완료`로 보존되고, 조회 화면에서 두 상태가 구분되어 표시된다. |
| 사후조건 — 실패·취소 | 상태 변경이 완료되지 않으면 기존 상태가 유지된다. 변경 이력·실패 기록의 보존 여부는 미확정이며, 보존 시 실제 개인정보를 포함하지 않는다. |
| 미확정 사항·고객 질문 | Q1. 상태를 변경할 수 있는 역할은 행정 담당자로 한정하는가?<br>Q2. `보관 중`과 `인도 완료` 외에 필요한 상태가 있는가?<br>Q3. 습득 학생이 등록한 물품은 어떤 상태로 시작하는가?<br>Q4. 상태 정정은 누가, 어떤 승인 절차로 수행하는가? 변경 이력을 보존해야 하는가?<br>Q5. 물품을 선택하기 위한 검색·식별 기준은 무엇인가? |
| 추가 검증 기준 | 상태 변경 후 조회 화면에 변경된 상태가 구분되어 표시되어야 한다. 상태 변경 권한과 정정 절차는 운영 전 확정해야 한다. |
