# 교내 분실물 관리 서비스 요구사항 추적표 (RTM v0.1.1)

## 1. 추적 기준

고객 요구사항 문서의 고객 요구 ID와 개발 범위·공통 제약을 SRS v0.1의 기능 요구사항(FR), 비기능 요구사항(NFR), 정책(Pol)에 연결한다. `보류`와 `제외`는 누락이 아니라 현재 릴리스에서 구현하지 않는다는 추적 결과다.

| 상태 | 의미 |
|---|---|
| 충족 | SRS에 구현 대상 요구사항으로 반영됨 |
| 보류 | 결정 또는 추가 확인 뒤 구현 여부를 정함 |
| 제외 | 현재 릴리스의 구현 대상이 아님 |
| 확인 필요 | 요구사항은 반영됐으나 세부 기준 또는 담당자 결정이 남음 |

## 2. 고객 요구사항 추적표

| RTM ID | 고객 요구사항 ID | 고객 요구사항 요약 | SRS 요구사항 ID | 추적 결과 | 상태 | 비고 |
|---|---|---|---|---|---|---|
| 01 | NEEDS_1 | 방문 전에 분실물의 보관 여부와 위치를 확인 | FR_01, NFR_01, NFR_04 | 조회 기능 및 이용·응답 기준으로 반영 | 확인 필요 | 검색 조건과 공개 항목은 OI_01, OI_02에서 확정한다. |
| 02 | NEEDS_2 | 물품 정보를 등록 | FR_02, NFR_02, NFR_04 | 습득 학생의 앱 직접 등록과 행정 담당자의 분실물 센터 관리용 등록 기능으로 반영 | 확인 필요 | 역할별 필수 입력 항목, 권한 및 검토·수정 절차는 OI_03에서 확정한다. |
| 03 | NEEDS_3 | 보관 중·인도 완료 상태를 기록하고 구분 | FR_03 | 상태 기록·표시 기능으로 반영 | 확인 필요 | 상태 변경 권한과 정정 절차는 OI_04에서 확정한다. |
| 04 | NEEDS_4 | 담당 부서와 문의 방법을 확인 | FR_04, NFR_01, Pol_06 | 문의 안내 기능으로 반영 | 확인 필요 | 표시할 상세 내용은 OI_05에서 확정한다. |
| 05 | NEEDS_5 | 습득물을 맡길 장소를 안내 | FR_05 | 제공 여부를 보류로 반영 | 보류 | 기존 안내 및 서비스 내 제공 필요성을 확인한다(OI_06). |
| 06 | NEEDS_6 | 필요한 공개 정보 범위를 정하고 개인 번호는 비공개 | NFR_03, Pol_01, Pol_03, Pol_07 | 개인정보 비공개 및 공개 항목 검토 정책으로 반영 | 확인 필요 | 개인 번호 비공개는 확정이며, 나머지 공개 항목은 정보보호 검토가 필요하다(OI_02). |
| 07 | NEEDS_7 | 행정 담당자의 물품 등록 부담을 경감 | NFR_02 | 등록 과제 수행 시간 목표로 반영 | 확인 필요 | 1차 일반 목표치는 90% 3분 이내이며, 운영 전 기준선·최종 목표를 확정한다(OI_07). |

## 3. 개발 범위 및 공통 제약 추적표

| RTM ID | 원천 ID | 원천 요구 / 제약 | SRS 요구사항 ID | 추적 결과 | 상태 | 비고 |
|---|---|---|---|---|---|---|
| 08 | C_1 | 가상 데이터만 사용하고 실제 개인정보·학교 인증 연동 제외 | NFR_03, Pol_01, Pol_02 | 데이터 및 연동 제한 정책으로 반영 | 충족 | 실제 개인정보 노출은 0건이어야 한다. |
| 09 | SC5 | 사진 업로드·유사 분실물 조회 | Pol_04 | 현 릴리스 범위 제외 정책으로 반영 | 제외 | 후속 개선 후보로 관리한다. |
| 10 | SC7 | 사진 매칭 결과 자동 알림 | Pol_05 | 현 릴리스 범위 제외 정책으로 반영 | 제외 | 수신 정보 등록과 발송 기능은 구현하지 않는다. |
| 11 | SC8 | 개인 휴대전화 번호 공개 | NFR_03, Pol_03 | 비공개 정책으로 반영 | 제외 | 담당 부서 문의 안내와 구분한다. |
| 12 | SC6 | 보관 담당자 문의 방법 안내 | FR_04, Pol_06 | 담당 부서 기반 문의 안내로 반영 | 확인 필요 | 담당 부서와 안내 문구는 OI_05에서 확정한다. |
